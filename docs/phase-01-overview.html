4.무엇이 어디서 실행되는가

phase-01 의 모든 코드는 본인 노트북 에서만 실행. Vercel·브라우저 코드는 phase-03 부터.

스크립트 실행 위치 용도 핵심 의존성
pnpm check:supabase 본인 노트북 연결 + pgvector + verses + embeddings + match_verses 검증 pg
pnpm fetch:bible 본인 노트북 OSIS XML 다운로드 → 정규화 JSON fast-xml-parser
supabase db push 본인 노트북 → remote DB 마이그레이션 적용 (verses 테이블, match_verses 함수) Supabase CLI
pnpm embed:bible 본인 노트북 JSON → 1pass INSERT · 2pass Gemini 임베딩 → DB UPDATE pg, @google/genai
pnpm eval:search (계획) 본인 노트북 평가셋 → cosine 검색 → 정량 hit rate + 정성 리포트 @supabase/supabase-js, @google/genai
왜 노트북 전용? Vercel 서버리스 함수는 10-60초 타임아웃. 31k 임베딩은 한도 안에서도 수십 분, 무료 tier 로는 31일 소요. 셋업·마이그레이션·배치 적재는 본질적으로 한 번 또는 가끔 실행하는 작업이라 노트북이 자연스러운 위치.

6.spec-01-05 미리보기 (현재 계획 중)

phase-01 의 마지막 spec. 머지 후 phase-01 종료 → develop → main.

핵심 제약: 1,000 verse 만 적재된 상태 → 평가셋의 정답 verse 는 Genesis 1~34 안에서만 구성. 범위 밖 (신약·시편 등) 은 사람 판단 정성 검증으로 처리. 정량 정확도 ≥ 60% 가 목표 (단, 미달 시 즉시 fail 처리 X — 원인 분석 + 사용자 협의).
