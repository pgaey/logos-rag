Phase 3: 인증 · UI · LLM 통합 (auth-ui-llm)

목표: phase-02 의 검색·프롬프트 조립 위에 Supabase Auth 로그인과 Next.js App Router 페이지를 얹고, Gemini Flash 를 호출해 한국어 답변 + 영문 근거 verse 가 함께 렌더링되는 엔드투엔드 사용자 흐름을 완성한다. 로컬에서 회원가입 → 로그인 → 한국어 질문 → 답변·근거 표시까지 사람 손으로 검증할 수 있는 MVP 가 결과물.

📦 예정 Spec 목록

spec-03-01

supabase-auth-setup

Supabase Auth 활성화 (이메일 + 1~2 개 소셜 provider, 예: Google), `@supabase/ssr` 기반 서버/클라이언트 헬퍼 작성, `middleware.ts` 로 보호 경로 세션 검증. env 추가 (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`).

spec-03-02

auth-ui-pages

App Router 페이지: `/login`, `/auth/callback`, 그리고 헤더에 로그인 상태/로그아웃 버튼. shadcn 등 가벼운 UI 라이브러리 또는 자체 컴포넌트로 최소 폼. 통합 테스트: 회원가입 → 이메일 확인 → 로그인 → 세션 유지.

spec-03-03

llm-gemini-client

`src/lib/llm/gemini.ts` — Gemini Flash 호출 wrapper (`@google/genai` 재사용). 입력: 완성 프롬프트 문자열, 출력: 한국어 답변 텍스트 + 인용된 verse 식별자(있다면). 타임아웃·재시도·에러 분기 구현, unit test (mock).

spec-03-04

qa-api-route

`app/api/qa/route.ts` — POST 핸들러. `{ question, k? }` 입력 → 인증 확인 → `searchVerses` + `buildPrompt` + `geminiAnswer` 순서 호출 → `{ answer, verses, prompt? }` 응답. 미인증 401, 입력 검증, Gemini 오류 매핑.

spec-03-05

qa-page-ui

`app/qa/page.tsx` — 질문 입력 textarea + 제출 버튼, TanStack Query mutation 으로 `/api/qa` 호출, 응답 렌더링: 한국어 답변 본문 + 근거 verse 카드 목록 (book chapter:verse + 영문 텍스트). 로딩/에러 UX. 사람 손 통합 테스트.

🔒 통합 테스트 후보 (Phase Done 조건)

시나리오 1 (인증): 회원가입 → 이메일 확인 → 로그인 → 세션 유지 → 로그아웃 PASS.
시나리오 2 (엔드투엔드 QA): 로그인 상태에서 한국어 질문 ("천지창조에 대해 알려줘") → 답변 본문이 한국어이고 근거 verse 카드 3~5건이 영문으로 표시 PASS.
시나리오 3 (미인증 차단): 로그아웃 상태에서 `/qa` 접근 시 `/login` 으로 redirect, `POST /api/qa` 는 401 응답 PASS.
주의: 임베딩 적재가 부분 (~3k/31k) 인 상태에서 진행됨 — Genesis·Exodus 외 책 질문에 대해 답변 품질이 낮을 수 있음. UI 자체의 통합은 검증 가능.
